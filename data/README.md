# Data

All files here are generated by the notebooks in `../notebooks/` — none are hand-edited. Run the
notebooks in order (`01` → `02` → `03` → `04`) to regenerate everything from scratch.

| File | Produced by | Description |
|---|---|---|
| `dos_ef_cache.json` | `01_data_acquisition.ipynb` | Raw, incremental cache of DOS(E_F) values keyed by Materials Project `material_id`. External data (Materials Project API); regenerates automatically on first run of Part 6, reused on subsequent runs. |
| `metals_dos.csv` | `01_data_acquisition.ipynb` | One row per sampled metal: `material_id`, `formula`, `crystal_system`, `energy_above_hull`, `dominant_element`, `family`, `period`, `dos_ef`. |
| `features.csv` | `02_eda_featurization.ipynb` | `metals_dos.csv` joined with MAGPIE compositional descriptors + one-hot crystal-system indicators, ready for modeling. |
| `cv_results.csv` | `03_modeling.ipynb` | Mean/std MAE for the three cross-validation schemes compared in Part 8 (ordinary K-fold, GroupKFold-by-family, GroupKFold-by-period). |
| `predictions.csv` | `03_modeling.ipynb` | Per-material actual vs. predicted DOS(E_F) from the held-out 80/20 split (Part 10), tagged `split` = train/test. |
| `lasso_coefficients.csv` | `03_modeling.ipynb` | Standardized Lasso coefficient per MAGPIE/crystal-system feature (Part 11). |

## External data not stored here

The raw Materials Project query result (`../cache/metals_query_cache.pkl`, ~72 MB — includes full
pymatgen `Structure` objects) is excluded from the repo since it's over the 50 MB limit. It is
regenerated automatically the first time `01_data_acquisition.ipynb` (Part 2) runs, given a valid
`MP_API_KEY` and internet access to `api.materialsproject.org`. See the project-root `README.md` for
setup instructions.
